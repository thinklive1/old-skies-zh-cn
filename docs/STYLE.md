# v1.1 文风规范

## 总体

对白写成自然、简洁的中文口语，忠实保留原文的信息、情绪和说话目的。避免“这对你有意义吗”“事情必须如此”“谢谢你的时间”等逐词搬运。不要给短句补充未经证实的背景、因果或人物关系。

## 不同文本类型

- 对话选项：简短、可扫描，明确行动或话题；“More about…” 通常写为“再说说……”。
- 对白：保留停顿、犹豫、反讽和强弱语气。不要机械地把每个 Well、Oh、You know 都译成独立句。
- 旁白与物品描述：自然、克制；不替玩家推断尚未发现的剧情。
- 新闻、档案、邮件：保留其文体，不把正式档案全部改成口语。名称、日期、地址、金额和搜索关键词尤其需要一致。
- 技术界面：用玩家熟悉的操作名称。测试与调试选项同样保留原有功能含义。

## 人物与设定

不依据单条译文字段臆造角色身份。尽可能阅读相邻对白，同一英文短句在不同情境下可以采用不同中文。不批量统一 Yes/No/Right/How 等高度依赖上下文的短句。

保留原汉化的人名、组织名和专门术语，除非英文与上下文提供明确的纠错依据。专名修订需更新术语表，并检查所有相关条目及图片文本。

## 标点与控制字符

中文正文采用中文标点，省略号通常用“……”。`&123` 是配音标记；`[` 是引擎换行标记；它们不是普通标点，不能擅自移除。保留原有格式占位符及顺序。标记相同不能证明意思正确，仍需人工核对。

## 字体

v1.0 使用裁剪字库。新增汉字必须通过覆盖检查；缺字时先判断是否可以用同样准确、自然且已有字形的表达。确需补字时应从具有合适授权的字体来源重建，并记录来源、许可及字形覆盖；不要用无授权的系统字体替换发布包。


## 审校范围调整（用户要求）

录音花絮、开发者解说及其标题保留 v1.0 原译，不做语言润色。已修改项须恢复上游文本。对白、旁白、界面、档案、物品与解谜提示继续全量审校。排除条目记录在 review/preserve_commentary.json。
